# Lot 4 — Adversarial evaluation plan and first executable baseline

Status: first synthetic baseline committed; **CI pending**.

## Method

Run the strict public `compare_handoff_validated` API against synthetic, locally generated bytes. Keep `PASS` limited to **local byte equality**; do not reinterpret it as independent agent receipt.

| Executable scenario | Expected outcome | Observable signal |
| --- | --- | --- |
| Identical sender and receiver local bytes | `PASS` | `EXACT_BYTES_MATCH` (local only) |
| Modified receiver bytes | `ALERT` | `HASH_MISMATCH` |
| Receiver bytes unavailable | `UNKNOWN` | `UNVERIFIABLE` |
| Receiver explicitly reports `not_checked` | `UNKNOWN` | `UNVERIFIABLE` |

Source: `tests/test_lot4_adversarial_baseline.py`. These cases execute the engine with actual temporary files. Results must not be claimed until the CI for the final published commit is green.

## Evaluation rules

- Track three outcomes, not only a binary pass/fail. A justified `UNKNOWN` is abstention, not a true negative.
- Measure `ALERT` precision, recall, false positives and false negatives only over cases with **defined alert vs non-alert ground truth**, and report the count/denominator. Do not infer quality from code coverage percentages.
- Maintain separate counts for unsupported parser/semantic verification, genuinely missing evidence, malformed inputs, and contradictory observed bytes.
- Do not treat the 17 Lot 1 contract cases marked `EXPECTED_RESULTS_ONLY_NOT_ENGINE_TESTS` as executed detections. Several expect structural checks that current runtime explicitly leaves `UNKNOWN`; do not silently overwrite their original expected outcomes.
- Never upload real user/client artifacts or secrets. No paid APIs or externally hosted processing is required for this baseline.
